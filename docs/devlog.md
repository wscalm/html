### 却下した案(理由)

- **装飾:** 次の「AI っぽい」定番の装飾はすべて却下。
  - 詩的なコピー、英字の小見出し、01/02 の番号、カルーセル
  - 数字を並べた統計ブロック、LIVE 表示、「解析」風の演出、ネットワーク図
  - 袋文字の大きなフッター、奥付、オレンジのアクセント、左に線を引いたタブ
- **導入:** 傾ける案と、箱にする案。
- **筐体:**
  - 質感を盛った筐体、銀のつまみ、表示窓、電源ボタン →「ブラウン管にない」「いらない」。
  - 上面と側面を描いて厚みを出し、スピーカーを横スリットにした版 → 最初の版のほうが良い。
  - 今後筐体を変えるときは、実装の前にラフを複数見せて選んでもらう。
- **小さな画面:** 番号と名前を光らせるデジタル表示の窓。
- **プロダクトの絵:**
  - ただ回る立方体 → ほかの 3 つに見せ場ができると「味気ない」。
  - 3×3×3 を 1 段ずつひねる立方体 →「趣味がルービックキューブみたい」。
- **経歴の絵:** 名刺・本・階段は採らず、ユーザーの発案で卒業帽にした。
- **SNS の絵:**
  - 吹き出し → 立方体・ロボット・卒業帽の固い立体と釣り合わない。
  - シェアアイコン・パラボラアンテナ・人工衛星 →「なんか違う」。ユーザーの発案の @ に決めた。

### 技術メモ(小さな画面の立体 ASCII アート)

- 実装は `script/script.js` の `mini3d`。canvas に 44×24 マスの等幅文字を `fillText` で描く。
- **描き方:**
  - 1 マスに 2×2 本の光線を当て、面の明るさを文字 `.:-=+*SW` に置き換える。面は `*` まで、`S`・`W` は辺と光る部品だけ。
  - 立方体は箱と光線の交差を直接計算する。ほかの絵は距離関数を少しずつたどって形に当てる(`sdfShade`)。
  - 明るさを負にしたマスは W/S のノイズとして描く(崩れる・固まる演出に使う)。
- **うまくいかなかったこと:**
  - 面の上の細かい区切りを明るい線にすると、斜めから見たときに詰まって W の塊になる。区切りは暗いすき間か、一段だけ明るい線にする。
  - 暗い側面に暗いすき間を引いても見えない。プロダクトの層の継ぎ目は一段明るくした。
  - 細い線の両側に輪郭線を引くと二重に見える(@ が同心円に見えた)。@ は輪郭線なしで、正面と側面の明るさの差で形を出す。
  - @ の外側の弧の終わりが内側のかぎに近いと、二重丸に見える。弧を手前で止めて、すき間を空けた。
  - @ を大きく振ると内側の a がつぶれる。線を細く、厚みを薄く、振れ幅を小さくした。
  - プリンターのヘッドの横棒は、小さい画面では斜めの棒にしか見えなかったので外した。
- **チャンネル替え:** W/S のノイズが絵にまとまる。1 秒に 25 コマほどに抑え、文字が切り替わる感じを残す。
- **動きを減らす設定の端末:** 各絵の `t0` の 1 コマで止める。
- **確認方法:** Playwright(WebKit)でローカル配信(`python3 -m http.server`)を撮る。

## 2026-11-27(続き 3) テレビの中の画面を作り直す

ブランチ: `feature/subpages`。トップ(ブラウン管・グリッチ・Unbounded のロゴ)を「正しい例」として、プロダクト・ボット・経歴・SNS をそろえた。

- **共通の部品:** 画面の頭に、テレビの右の小さな画面と同じ 3D の ASCII アート(`mini3d` を別の canvas にも描けるようにした)とチャンネル番号。スクリーンショットやアプリは黒い縁の画面(走査線とガラスの映りこみ)に映す。
- **プロダクト:** 3 作品を黒い縁の画面に。カーソルで光の帯が走り、ちらつく。URL を等幅で添える。作品の画面のギャラリーも同じ縁に。
- **ボット:** bot のアイコン・説明・X と Bluesky のアカウント、しくみの端末(`crontab -l`、コマンド名は飾り)。Bluesky の最新の投稿 4 件を、テレビの 2 チャンネルと同じアプリの画面に出す(読めなければ投稿の例)。
- **経歴(モック):** 大きな端末の画面。`whoami`・`git log --graph`(大阪の高校 → 岡山大学 → 岡山大学大学院で自然言語処理 → 東京の IT 企業でフルスタック)・`cat research.txt`・`tree skills`・`cat now.txt`・`ls works/`。画面に入ると 1 行ずつ出る。年・学部・研究科・研究テーマは伏せ字、skills の中身は仮。
- **SNS:** プロフィールと、テレビの筐体と同じ白い樹脂の板に小さな画面を付けたアカウント。アイコンは 16×16 のドット(X・Bluesky・GitHub・メール、仮置き)。準備中は W/S の砂嵐。
- **読みやすさ:** 背景の W/S が文字に重なって読みにくかったので、`data-quiet` の要素(ヘッダーのロゴとメニュー、もどるボタン、見出しや本文)の下だけ W/S を薄くし、カーソルの丘や波も立てない(シェーダーに四角を最大 24 個渡す)。
- **テレビへもどる:** これまでは W/S のノイズでテレビを描き直していたので「中から外へ出た」感じがなかった。いまのページを写してテレビの画面の中に置き、画面いっぱいまで寄っていたテレビからカメラが引くように元の大きさへもどす。引くにつれて走査線とガラスが乗り、最後に写しがちらついて消えて番組に替わる。もどるボタンも小さなテレビのアイコンにした。
- **SNS の中身:** GitHub @wscalm・X @wsws_tech・メール wsws.works@gmail.com。Bluesky は bot だけで個人では使っていないので載せない。テレビの 4 チャンネルも同じ 3 つにした。
- **テレビと画面のつながり:** テレビで見ていた番組と、入った先の画面の印象が違う(特に経歴は端末だけだったのに、入ると周りに W/S の背景がある)のが「直感と違う」。番組と同じ役目の部分を決めて、そこを橋にした。
  - 入るとき: 全面に広がった番組の板が、その部分へ縮んでおさまり、本物と入れ替わる。周りの部品はそのあいだにちらつきながら出る。経歴は端末の窓、ボットは投稿のアプリの画面、SNS はアカウントのまとまり、プロダクトはテレビに映っていた作品の画面。
  - もどるとき(逆): その部分が番組の板に替わりながら画面いっぱいに広がり、周りはちらついて消える。そこからカメラが引いてテレビにもどる。ページを丸ごと写してテレビに入れる案は、最後に番組へ切り替わる所でまた印象が変わるのでやめた。
  - 出入りの写しと、もどった直後のテレビでは、端末の行を打ち直さない(行が消えて打ち直されると、つながりが切れて見える)。
- **切り替わりのグリッチ:** 画面を替えた瞬間に描き直しでカクついたり大きさが飛んだりするのを、グリッチの演出でごまかす(「そういう世界ね」と思わせる)。テレビの画面が板に替わる瞬間・ページが替わった瞬間・板と本物が入れ替わる瞬間・テレビにもどって引き始める瞬間・引き終わり、に W/S のノイズの帯と細い反転の帯を数コマ走らせ、板を横にずらして明滅させる。板と本物の入れ替わりも、なめらかに薄めず段で行き来させる。画面を替えた直後の重いコマで動きが先へ飛ばないよう、動きの時計は最初のコマから数え、引き始めは少し待つ。
- **もどるときは「はじき出される」:** 入るときの逆(つなぐ部分が番組に広がる)だと、プロダクトから戻るたびに長い言葉のデータベースが選ばれた状態になって気になる。入るときは「グリッチを抜けてなんとか入れた」、出るときは「出ていけとバンと追い出された」にして、どの画面からも同じ動きにした。画面がガタガタ揺れて上下に裂け、ブラウン管を切ったように横一本の線へつぶれる(約 0.4 秒)→ 画面いっぱいまで寄ったテレビは砂嵐がバリバリ鳴っている → カメラが勢いよく引き、半ばで砂嵐が止んで元の番組(作品の画面は戻る前に映っていたもののまま)にパッともどる。板を写す方法と、見えないトップを測るための is-measuring はやめた。

## 2026-11-27(続き 4) 文字の読みやすさ・スマホの背景・使っている技術・経歴

ブランチ: `feature/subpages`。

- **文字の下の白い板をやめる:** `data-quiet` の下だけ W/S を薄くしていたのが、白い板を敷いたように見えてサイトの中で浮いていた。行ごとに W/S を 1 文字ずつ抜く案は「大して変わってない」。いまは W/S を文字の下でも途切れさせず(真下だけ 25% 薄く)、丘と波だけ行の 3 マス手前から収める。文字には字の形に沿った細い白いふち(`text-shadow`)を付けて分ける。静かにする四角は、まとまりの外枠ではなく行ごとに測る(最大 64 個)。
- **スマホでも丘と波:** カーソルのない端末(`hover: none`)では、見えないカーソルが画面の中をゆっくりさまよって(約 70px/秒、ときどき行き先を変える)、1.4〜3.6 秒おきに弱い波を出す。触っている間は指に従い、離して 1.8 秒でその場からまたさまよう。さまよう間は 30 コマ/秒。動きを減らす設定では動かさない。
- **使っているもの:** 作品の画面に、画面・アプリ・データベース・サーバーなどを罫線だけの表で載せた。ロゴは Simple Icons(CC0)の形をブランドの色で(16×16 のドットにすると Flask・Rails・PostgreSQL・MySQL がつぶれて読めなかった)。
  - 長い言葉: v1・v2 は Flask と PostgreSQL、v3 は Rails と MySQL。版のタブで行(`data-gen`)が切り替わる。Claude Code と GitHub Actions は v3 だけ。MeCab・VPS(Ubuntu)・Nginx・Cloudflare(.com は .jp へ 301)は共通。
  - Bookshelf: HTML・CSS・JS と、本のデータを作る Python。Claude Code。ロンバーグ: math.js・decimal.js・Chart.js(Claude Code は使っていない)。
  - ロゴのないもの: MeCab は自作の双葉(名前の由来は和布蕪。最初の葉 1 枚は「緑のラグビーボール」と言われた)。math.js は公式の色 #dc3912 の四角に白い m、decimal.js は公式の文字のロゴから等幅の d と赤い点。札の中では白いふちがにじむので外した。

## 2026-11-28 描画を軽くする・不具合の直し・スクリーンショットの差し替え

ブランチ: `feature/subpages`。コードレビュー(効率と描画の遅れ)で出たものを、重い順にすべて直した。

- **小さな画面の 3D(mini3d):** 光線の内側のループで `Math.hypot` をやめて `Math.sqrt` に(絵は 1 マスも変わらないことを確かめた。計算は 2〜3.5 倍速い)。文字は見本帳から `drawImage` で写す(`fillText` を毎コマ約 1000 回呼ばない)。画面の外では `IntersectionObserver` で止める。使っていなかった ASCII アートの経路(MINI_ART)は消した。
- **画面を移る演出:** 画面を替えるコマと、次の画面を測って文字の層を描くコマを分けた。canvas は大きさが変わったときだけ確保し直す。毎コマ塗る四角は横に続くマスでまとめる。演出の canvas は画素密度 1.5 まで。グリッチの層は使わない間は放す。ヘッドレス(ソフトウェア描画)で測ると、経歴へ移るときの長い処理が 3.4 秒 → 0.07 秒。
- **背景:** スマホのさまよいは、画面に入る・触ってから 15 秒で休む。演出が画面を覆っている間は描かない。スクロールでは行の位置を測り直さず、ページの座標でとっておいた四角をずらすだけ。`preserveDrawingBuffer` を外した。ツールバーの出入り(高さだけの変化)ではマス目を作り直さず、演出も打ち切らない。スマホの下の帯とヘッダーのぼかし(`backdrop-filter`)はやめて白に。文字の白いふちは 4 層 → 2 層。
- **画像と書体:** サムネイル用に 160×100 の画像を作った(`images/works/thumbs/`、20 枚で約 73KB)。Google Fonts の CSS は描画を止めないよう後から効かせ、使う太さだけ読む。導入がないとき(動きを減らす設定)は、書体がそろうまで最大 0.8 秒白で待つ(届く前の書体が一瞬見えないように)。
- **不具合:** テレビから入ったあと、つなぐ部分がもう一度ちらつく / サムネを素早く押すと大きい画像が食い違う / トップへはじき出されるとき前後のボタンが飛ぶ / 端末で `cat __proto__` などで止まる / 準備中のアカウントに砂嵐が出ない / ボットの時計が毎時 0 分に 60:00 / 版を素早く替えると砂嵐が早く止まる / 導入中に URL が変わっても合わせない。
- **スクリーンショット:** 長い言葉 v3 を差し替え(トップ・単語の詳細・収録統計・絞り込みとハイライト・ランキング)。Bookshelf は booklog の main(179 冊、2026.11 まで)で撮り直し。撮るのは WebKit(このマシンの Chromium は Google Fonts を読めず、文字が抜ける)。

## 2026-11-28 音を付ける

ブランチ: `feature/sound`(`fix/cache-bust` の d72b997 の上。main に .deployignore の戻しがまだ入っていないので、この上で作った)。

- **はじめはオフ:** ヘッダーのメニューの右に、ドットのスピーカー(16×16、切っているときは × で少し薄い)。押すと入り、入れた・切った状態は localStorage(`wsws-sound`)に覚えておく。ブラウザの決まりで、押す・打つより前は鳴らせないので、初めの導入は無音。
- **方向性:** 「ブラウン管と電脳」。テレビの部品は本物の機械の音、W と S の演出はデジタルのピリピリ。電子音(ピコピコ)と、押したときだけの控えめな案は採らなかった。
- **作り方:** `script/sound.js` で Web Audio を使ってその場で合成する(音声ファイルは置かない)。script.js からは `wsSound.play('click')` のように呼ぶ。鳴らせないとき(オフ・まだ押していない・古いブラウザ)は何もしない。止まっているうちに予約すると、開いたとたんにまとめて鳴るので、押した直後でなければ予約しない。

| 場面 | 音 |
|---|---|
| つまみ・チャンネル替え | カチッ(戻り止め)+ ザッ(砂嵐 0.3 秒)。番組のない 5・6 は小さな砂嵐が鳴り続ける |
| 電源・音を入れたとき | ボンッ → かすかにジー(電源のうなり)。音を切るときはプツッ |
| テレビから入る | ピリッ + シュッ(板が広がる)→ ページが替わる所と板が本物と入れ替わる所でピリピリ |
| はじき出される | ガガッ(揺れて裂ける 40 ミリ秒ごとに途切れる)→ プツン(音程が落ちて切れる)→ 砂嵐のザー + ヒュッ(カメラが引く)→ ピタッ(番組にもどる) |
| 画面の移動 | W と S が覆う間のピリピリと、部品が本物に替わるときのパチパチ。流れてくる側から聞こえる |
| 版の切り替え | キュルキュル(新しい版へは上がり、古い版へは下がる)→ 止まるときのガチャ |
| ギャラリー | 小さなザッ |
| 経歴の端末 | 行が出るたびにカタッ(打ちこんだ行はコツ)。打鍵はコツ、Enter は低め。`sl` は汽笛のポーッと、右から左へ走り抜けるシュッシュッ |

- **鳴らさないもの:** カーソルを合わせたとき、プロダクトの番組が自動で替わるとき、小さな画面の絵の動き(勝手に何度も鳴ると気になるので)。
- **音量:** OfflineAudioContext に書き出して測り、チャンネル替え(50 ミリ秒ごとの最大で約 -23 dB)を基準にそろえた。電源のボンッは音を入れた瞬間にも鳴るので、驚かせないよう小さめ。全体は 0.5 倍で、重なっても割れないようコンプレッサーを通す。
- **キャッシュ:** 同じ日に 2 度目の変更なので、style.css と script.js は `?v=20261128-2`。

### 2026-11-28(続き) ピコピコをやめる・導入に音・導入のノイズを短く

- **ピコピコをやめる:** グリッチのピリピリに混ぜていた矩形波の粒(音程のある電子音)と、ピタッの電子音を外した。粒はどれも雑音にした。
- **導入の音:** 大きなノイズ(地鳴りが上がっていき、グリッチの帯と同じ時刻にガリッ、形が一瞬見えるときにジッ・ドゥッ、白に溶けるパチパチ、形が残るストン)→ 大きな W(ちらついてドン、溜めて 3 つにシュバッ、ピタッ、文字の切り出しのカッ)→ テレビ(文字が集まるザーッとカチカチ、組み上がりのピタッ、細かく割れるパリパリ、上から描き変えるニュイーン)→ 電源のボンッ。スキップや画面の大きさの変更で打ち切ったら音も引っこめる。
  - 音を入れている人は、読み込んだときに音の出口を作っておき、導入はそれが開くのを 0.25 秒まで待つ。
  - **ただし、ブラウザの決まりで、たいていは鳴らない。** Chromium で試すと、押したあとのリロード(F5・更新ボタン)では押すまで開かない。サイト内のリンクで同じサイトへ移ったときだけ、押す前に開いた。Safari は押すまで開かない。サイトに自動再生を許可しているブラウザでは鳴る。
- **導入のノイズを短く:** 大きな W(ほかの画面から始まるときは画面の形)ができるまでを以前の 0.8 倍にした(トップは形が本物に替わるまで 3.3 秒 → 2.64 秒)。
- **グリッチを後半ほど増やす:** 帯と四角の数を 64 → 110(トップ)、70 → 120 にし、時刻の 2 乗に比例して後半に寄せた(序盤は以前と同じくらい、終盤は以前の約 3 倍)。後半ほど帯は太く、大きくずれ、四角は大きい。反転は以前どおり 1 行の細い帯と小さな四角だけで、各コマの平均の明るさとコマ間の変化は以前とほぼ同じ。
- **音割れ:** コンプレッサーの自動の持ち上げで、立ち上がりの速い音が 0 dBFS を超えることがあったので、出口の最後で 0.7 を超えた分をなめらかに丸める。

### 2026-11-28(続き 2) 音を入れている人は「押すと始まる」

- 導入中に押すとスキップになるので、Chrome などでは導入の音を聴く機会がなかった(押すまで音を出させないため)。
- 一度音を入れた人が開き直したとき、まだ音を出せなければ、導入の前に白い画面にスピーカー(ゆっくり点滅)と「押すと始まる」を出して待つ。画面のどこかを押す(Enter・Space も)と、音付きで導入が最初から始まる。
- スキップのボタン・Esc などほかのキー・ホイールは、今までどおりスキップ(押した操作なので、電源のボンッからは鳴る)。
- 音がオフの人、ブラウザがはじめから音を出させる場合、動きを減らす設定(導入がない)では出さない。
- **やめた(同じ日):** 開いたらまず押させるのは、音を聞かせるのを押しつけることになり、満足度が下がる。導入の前の「押すと始まる」は取り外し、導入はまた、ブラウザが音を出させるときだけ鳴る形に戻した。
